# omp Claude Subagent Style

ompの入力欄の下に、Claude Code風のサブエージェント一覧を固定表示する拡張です。

Claude Code風に合わせる対象は見た目と操作感だけです。サブエージェントの起動・実行方式、モデル、ツール、プロンプト、権限、並列処理や結果の自動配信は変更しません。

```text
› ● main
  ○ explore      ホーム直下の構成確認             12s · ↓ 4.3k tokens
  ○ test-runner  テストの実行                     10s · ↓ 15.1k tokens
```

## 導入

omp 18.10.2以降、Bun 1.3.14以降を対象としています。描画にはompが提供する `@oh-my-pi/pi-tui` を使用します。ビルドは不要です。

### Marketplaceからインストール

```sh
omp plugin marketplace add uta-a/omp-claude-subagent-style
omp plugin install omp-claude-subagent-style@uta-a-omp-plugins
```

インストール後はompを再起動してください。

ompのチャットから登録する場合:

```text
/marketplace add uta-a/omp-claude-subagent-style
/marketplace install omp-claude-subagent-style@uta-a-omp-plugins
```

更新する場合:

```sh
omp plugin marketplace update uta-a-omp-plugins
omp plugin upgrade omp-claude-subagent-style@uta-a-omp-plugins
```

### ローカルで試す

このディレクトリで、一度だけ読み込む場合:

```sh
omp -e ./index.ts
```

通常起動でも読み込む場合、このディレクトリでリンクしてください:

```sh
omp plugin link .
```

リンク後はompを再起動してください。別のディレクトリからリンクする場合は、`.` の代わりにこのパッケージの絶対パスを指定します。

## 表示の仕様

- 表示位置は入力欄の下。先頭に太字の `main`、続いて種類名と作業の説明を表示します。`›` は選択位置、`●` は現在表示している会話、`○` はその他の会話です。
- 一覧の上下に1行、左右に2文字分の余白を設けます。極端に狭い端末では左右の余白を縮めます。
- エージェントの種類を表示します。画像の `ensemble:` のような接頭辞は、実際の種類名に含まれる場合のみ表示します。同じ種類を複数起動した場合は、個別の行と時間を保持します。
- 説明はompの進捗通知の要約を使用し、なければ最新の作業意図やタスク本文を使用します。
- 経過秒と `↓ トークン数 tokens` は右寄せです。トークン数はompの累積値（入力・出力・キャッシュ書き込みの合計、キャッシュ読み取りを除外）で、出力トークンのみではありません。未取得は `—`、1,000以上は `4.3k` のように表示します。
- 日本語・絵文字の表示幅を考慮し、長い説明は省略します。狭い端末ではエージェント名を優先し、端末幅の変更に追従します。
- 実行中は毎秒更新。ompの進捗通知に含まれる実行時間で補正します。秒未満は切り捨てます。
- 完了・失敗・中断したエージェントは、通知を受けた時点でその都度非表示にします。すべて終了すると一覧も消えます。遅れて届いた進捗では再表示しません。
- 表示中のエージェントが終了した場合は、mainの会話へ自動で戻ります。
- 完了表示はomp標準のものを使用します。この拡張は独自の完了メッセージを追加せず、標準の完了表示の内容・色・配信を変更しません。
- 同期・バックグラウンドの両方のサブエージェント通知に対応します。eval経由の起動も、同じライフサイクル通知が届けば表示されます。
- 新しいセッションでは一覧をリセットします。拡張読み込み前の履歴は復元しません。
- 子セッションやヘッドレス実行ではウィジェットを作成しません。
- omp標準のツールカードやサブエージェントHUDは変更・非表示にしません。この拡張はコンパクトな一覧を追加します。

## omp標準表示との併用

この拡張の一覧を使う場合、omp標準のPinned Subagentsはオフにして構いません。`display.pinnedAgents` を `off` にすると、入力欄の上にある標準の固定一覧だけが消えます。この拡張の一覧、上下キーの選択、会話切り替えやサブエージェントの実行には影響しません。

設定ファイルで指定する場合:

```yaml
display:
  pinnedAgents: off
```

`Background job completed` や `job settled` などの標準完了表示はPinned Subagentsとは別です。この設定では消えません。この拡張はユーザーの設定を自動変更しません。

## キーボード操作

入力欄が空のとき、`↑` / `↓` でmainと実行中のエージェントを選択します。循環はしません。`main` で `↑` を押すと一覧の選択操作を解除してプロンプト入力へ戻ります。末尾で `↓` を押しても、その行で止まります。

- `Enter`: 選択したエージェントのライブ会話を、ompの通常の会話表示領域に表示します。
- `main` を選んで `Enter`: 元のmainの会話へ戻ります。
- `Esc`: 一覧の選択操作を解除し、omp標準の動作へ戻します。エージェント表示中・入力欄が空ならmainへ戻ります。
- 入力欄に文章がある場合は、上下キーとEnterは通常の編集・送信として動作します。一覧の操作を始めていないときのEnterも標準の動作です。

会話のコピーをmainの履歴に追加する方式ではなく、omp標準の会話ビューを切り替えます。エージェント表示中に送信したメッセージは、そのエージェント宛てになります。

拡張は `CustomEditor` のサブクラスを設置し、ホストが提供する `onFocusAgent` を使用します。他の入力欄置換拡張との併用では、後から設置された入力欄が優先されます。キーボード操作はローカルの対話TUI向けです。

## 検証

```sh
bun install
bun test
```

独立した経過時間、完了・失敗・中断時の即時削除、遅延通知、同種の複数起動、再実行、末尾での選択停止、mainから上キーでプロンプト入力へ戻る動作、Enterによる会話選択とmainへの復帰、表示中の終了、通常の編集・送信、セッション切替・終了時の解除、ヘッドレス動作、説明とトークン数の更新、幅0〜120列での日本語・絵文字の省略と右寄せを検証します。

omp 18.10.3の実際のTUIで、SDKで作成した2つの一時サブセッションにテスト用の会話を設定し、`↓` + `Enter` で子の会話が表示されること、`↑` + `Enter` でmainへ戻ること、終了通知で一覧が即時に消えることを確認しました。モデルへのリクエストは行っていません。

独自の完了表示を追加しないことも同じTUIで確認済みです。テスト用の進捗・ライフサイクル終了通知を2件ずつ送ると一覧が消え、拡張から追加の完了行が出ないことを確認しました。回帰テストでは完了時のmain復帰と一覧削除を維持しつつ、独自の通知・メッセージ送信がないことを検証します。

境界動作は実際のTUIでも確認済みです。末尾で繰り返し `↓` を押しても同じ子の選択を維持し、mainで `↑` を押した後は `Enter` が一覧の会話選択ではなく入力欄の送信に戻ること、続けて文字入力・送信できることを確認しました。モデルへのリクエストは行っていません。
